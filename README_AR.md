# Weekly Telegram Organizer — Cloudflare Edition

نسخة جديدة مبنية من البداية لتعمل على **Cloudflare Workers + D1** باستخدام Telegram Webhook. لا تحتاج إلى Python أو سيرفر دائم، ولا يتم تنزيل ملفات PDF والصوتيات إلى Cloudflare؛ يحتفظ البوت ببيانات الرسالة و`file_id` و`chat_id` و`message_id` ثم ينسخ الرسالة من محادثة البوت إلى القناة باستخدام Telegram Bot API.

## ما الذي يفعله البوت؟

- لوحة تحكم بأزرار Telegram، وليس أوامر نصية في الاستخدام اليومي.
- بدء أسبوع جديد، ثم إدخال رقم الأسبوع يدويًا مرة واحدة.
- استقبال الرسائل والملفات المحوّلة إلى المحادثة الخاصة مع البوت بأي ترتيب.
- تصنيف تلقائي إلى Lectures أو Sections أو Summaries.
- تعرف على المواد الست بالترتيب والهاشتاجات الرسمية:
  1. AIS — `#AIS`
  2. Cost System — `#cost_system`
  3. MA — `#Managerial_ACC`
  4. FR — `#FR`
  5. Advanced — `#Advanced_Managerial_ACC`
  6. دراسات محاسبية — `#دراسات_محاسبية`
- كل المستندات التابعة للمحاضرة، بما فيها Assignments وHandouts وWorksheets والملفات الإضافية، تظل ضمن Lectures. تأتي الملفات غير الصوتية أولًا، ثم التسجيل الصوتي، ثم الرسالة التعريفية التي ينشئها البوت.
- Sections مستقلة، بنفس ترتيب المواد. عند اكتشاف رقم السكشن يرتب تصاعديًا، ويضع ملفات Answers بعد ملفات السكشن الأساسية. رقم السكشن يُستخرج من اسم الملف (مثل Sec 2) ولا يُستبدل برقم محاضرة الأسبوع.
- بعد السكاشن ينشئ رسالة ختامية مثل `☝🏻 سكاشن الأسبوع الثاني` عند وجود رقم سكشن واحد واضح، أو يعرض الأرقام المكتشفة إذا تعددت.
- Summaries مستقلة، بنفس ترتيب المواد. عند اكتشاف رقم المحاضرة يرتب تصاعديًا، ثم يضيف الرسالة `☝🏻 ملخص محاضرة كل مادة الأسبوع ده`.
- المواد أو السكاشن أو الملخصات الناقصة لا تُنشأ من تلقاء نفسها؛ ينشر البوت العناصر التي وصلته فقط.
- يضيف الهاشتاج الرسمي للمواد في منشورات Sections وSummaries. لو نوع الرسالة لا يدعم Caption، يرسل الهاشتاج في رسالة نصية مستقلة بعدها.
- معاينة قبل النشر، تصحيح يدوي للقسم والمادة، وتجاهل أي عنصر مع الاحتفاظ به في سجل العملية.
- نشر على دفعات صغيرة لتجنب تجاوز حدود الطلب الواحد، مع حفظ تقدم النشر في D1.
- يعالج إعادة إرسال Webhook لنفس `update_id` دون تكرار حفظ العنصر.

## متطلبات التشغيل

- حساب Cloudflare مجاني.
- Node.js 20.6 أو أحدث على الكمبيوتر لإعداد Wrangler والنشر.
- Bot Token من `@BotFather`.
- Telegram User ID الخاص بك.
- قناة النشر، مع إضافة البوت إليها كمسؤول ومنحه صلاحية نشر الرسائل.

## إعداد Cloudflare

### 1. فك الضغط وتثبيت Wrangler

داخل مجلد المشروع:

```bash
npm install
npx wrangler login
```

### 2. قاعدة D1 الموجودة

المشروع مضبوط على قاعدة D1 الحالية المرتبطة بالـWorker باسم `organizer` وبمعرّفها الحالي. لا تنشئ قاعدة جديدة ولا تغيّر `database_id`؛ تطبيق migrations على قاعدة أخرى سيجعل Worker يعمل على قاعدة فارغة أو مختلفة.

### 3. إدخال بيانات المالك

ملف `wrangler.jsonc` مضبوط على رقم حساب المالك `6453532232` واسم الـWorker الحالي `weeklyorganizer`. لا تغيّر الرقم إلا إذا تغيّر حساب المالك.
`CHANNEL_ID` اختياري تمامًا ولا يلزم ضبطه. البوت سيطلب وجهة النشر من داخل المحادثة عند أول نشر إذا لم يكن هناك وجهة محفوظة للأسبوع.

عند الضغط على زر «نشر المحتوى» وإذا لم يكن `CHANNEL_ID` مضبوطًا، سيطلب منك البوت وجهة النشر في المحادثة الخاصة. يمكنك إرسال أحد الخيارات التالية:
- `@channelusername` للقناة العامة.
- `-1001234567890` كـ Chat ID للقناة الخاصة.
- رابط `https://t.me/channelusername` للقناة العامة.

بعد إدخال الوجهة، يحفظها البوت مع الأسبوع الحالي في D1 ويستخدمها عند استكمال النشر. يجب إضافة البوت إلى القناة كمسؤول ومنحه صلاحية نشر الرسائل. إذا ضبطت `CHANNEL_ID` لاحقًا كمتغير بيئة، فسيكون هو الوجهة الافتراضية لجميع عمليات النشر.

### 4. إنشاء الجداول في D1

```bash
npx wrangler d1 migrations apply organizer --remote
```

### 5. إضافة الأسرار

أنشئ قيمة طويلة عشوائية لـ `WEBHOOK_SECRET` من أحرف إنجليزية وأرقام و`_` و`-` فقط.

```bash
npx wrangler secret put BOT_TOKEN
npx wrangler secret put WEBHOOK_SECRET
```

الصق القيمة المطلوبة عند مطالبة Wrangler بها. لا تضع التوكن داخل `wrangler.jsonc` ولا ترفعه إلى GitHub.

### 6. نشر Worker

```bash
npx wrangler deploy
```

سيظهر عنوان شبيه بـ:

```text
https://weeklyorganizer.koala-x66.workers.dev
```

افتح `https://weeklyorganizer.koala-x66.workers.dev/health`. يعرض الفحص صلاحية BOT_TOKEN، وتطابق Webhook، واتصال D1، ووجود الجداول وأعمدة migration 0002، ولا يعرض أي قيمة سرية. يجب أن تكون عناصر `checks` صحيحة قبل بدء تنظيم أسبوع.

### 7. تسجيل Webhook مع Telegram

انسخ الملف `.webhook.env.example` إلى ملف جديد اسمه `.webhook.env` في جذر المشروع، ثم أدخل:

```env
BOT_TOKEN=YOUR_BOT_TOKEN
WEBHOOK_SECRET=THE_SAME_SECRET_YOU_ADDED_TO_WRANGLER
WORKER_URL=https://weeklyorganizer.koala-x66.workers.dev
```

ثم شغّل:

```bash
npm run webhook:set
```

لفحص حالة Webhook:

```bash
npm run webhook:info
```

يمكنك أيضًا فتح `/health` في المتصفح؛ سيقارن رابط Webhook المسجل بالرابط الفعلي للـWorker ويتأكد من صلاحية التوكن ووصول D1.

هذا الملف مستثنى من Git عن طريق `.gitignore`. لا تشاركه ولا ترفعه إلى مستودع عام.

## الاستخدام من الهاتف

1. افتح محادثة البوت واضغط Start أو `/start` مرة واحدة.
2. اضغط زر **أسبوع جديد**.
3. اكتب رقم الأسبوع مرة واحدة، مثل `6`.
4. اعمل Forward لكل ملفات ورسائل الأسبوع إلى المحادثة الخاصة مع البوت. لا يلزم ترتيبها قبل الإرسال.
5. عندما تنتهي اضغط **إنهاء الاستقبال**.
6. راجع **معاينة الترتيب**. عالج العناصر غير المصنفة من **تصحيح التصنيف** أو استبعد غير المطلوب من **تجاهل عنصر**.
7. اضغط **نشر المحتوى** ثم أكد النشر.
8. ينشر البوت حتى 4 عناصر في الدفعة الواحدة. إذا بقي محتوى، اضغط **متابعة النشر** حتى يكتمل.

## ترتيب النشر بالتفصيل

### Lectures

ترتيب المواد: AIS ثم Cost System ثم MA ثم FR ثم Advanced ثم دراسات محاسبية.

يظهر فاصل خطي قبل المجموعة. رقم المحاضرة في الرسالة الختامية هو رقم الأسبوع الذي أدخله المستخدم.

داخل كل مادة: كل الرسائل والمستندات غير الصوتية التي استلمها البوت (Lecture PDF وNotes وAssignments وHandouts وWorksheets والمواد الإضافية) بترتيب وصولها، ثم التسجيلات الصوتية، ثم رسالة المحاضرة مع رقم الأسبوع/المحاضرة والهاشتاج الدقيق.

### Sections

قسم مستقل بعد Lectures، ويبدأ بفاصل خطي. يرتب حسب المواد نفسها. أرقام السكاشن المستخرجة من اسم الملف ترتب تصاعديًا، وتأتي ملفات Answers بعد الملفات الأساسية للسكشن نفسه. رقم السكشن مستقل عن رقم المحاضرة/الأسبوع الذي أدخله المستخدم. يضاف هاشتاج المادة إلى Caption أو نص الرسالة، أو في رسالة منفصلة عندما لا يسمح نوع الوسائط بإضافة Caption. ينتهي القسم برسالة مثل `☝🏻 سكاشن الأسبوع الثاني` وفق رقم Sec المستخرج.

### Summaries

قسم مستقل بعد Sections، ويبدأ بفاصل خطي. يرتب حسب المواد نفسها، ثم رقم المحاضرة إذا أمكن استخراجه. يضاف الهاشتاج الرسمي بالطريقة نفسها. بعد آخر ملف يضيف البوت `☝🏻 ملخص محاضرة كل مادة الأسبوع ده`.

المواد التي لا تحتوي على ملفات في قسم معين يتم تجاوزها ولا تُنشأ لها ملفات أو منشورات وهمية.

## الفواصل

الفواصل الحالية خطوط نصية بسيطة مثل الخطوط الظاهرة في صور القناة، وموجودة في `src/logic.js` داخل `GROUP_DIVIDERS`. يمكن تغييرها بسهولة. رسائل ختام السكاشن والملخصات معرفة في `makeSectionsFooter` و`SUMMARIES_FOOTER`.

## نقاط مهمة وحدود

- يجب إرسال الملفات إلى المحادثة الخاصة مع البوت؛ لا يحتاج البوت إلى الدخول إلى قناة المصدر.
- `copyMessage` ينسخ الرسالة التي وصلته إلى القناة. الرسائل المحمية أو الأنواع التي لا تسمح Telegram بنسخها قد تفشل، وسيعرض البوت خيار إعادة المحاولة أو التخطي.
- لا يحذف البوت أي شيء من المصدر.
- لا ينشر قبل التأكيد.
- إذا عملت Forward للفواصل أو رسائل الختام القديمة للمحاضرات/السكاشن/الملخصات، يتعرف عليها البوت ويتجاوزها لأنه سيعيد إنشاء النسخ الجديدة برقم الأسبوع ورقم السكشن المستخرجين.
- إذا انقطع Worker بعد إرسال رسالة وقبل حفظ نجاحها في D1، قد تصبح حالة هذا العنصر غير مؤكدة. سيطلب البوت منك مراجعة القناة ثم اختيار إعادة المحاولة أو التخطي لتقليل احتمال التكرار.
- أضف البوت كمسؤول في القناة مع صلاحية نشر الرسائل.
- لا تشغل نسخة Long Polling قديمة بالتوكن نفسه بعد تسجيل Webhook؛ Telegram لا يسمح باستقبال `getUpdates` مع Webhook فعال.
- هذه النسخة تعتمد على Worker Free وD1 Free ضمن حدود الاستخدام الحالية. راجع صفحة Cloudflare Limits وD1 Pricing لأن الحدود والسياسات قد تتغير.

## تشخيص الأخطاء

- `401` على `/telegram/webhook`: قيمة `WEBHOOK_SECRET` في Cloudflare لا تطابق `secret_token` المسجل لدى Telegram.
- `500` على `/telegram/webhook`: راجع Exception في Worker Logs؛ النسخة الحالية تسجل الخطأ الأصلي، وتضع عملية D1 داخل كتلة المعالجة حتى لا تضيع تفاصيل الاستثناء.
- `/health` يعرض `requiredTablesPresent=false`: طبّق `npx wrangler d1 migrations apply organizer --remote`.
- `/health` يعرض `optionalChannelMigrationApplied=false`: migration `0002` لم تُطبّق على قاعدة `organizer` بعد؛ نفّذ أمر migrations أعلاه.
- `/health` يعرض `botTokenValid=false`: التوكن غير صحيح أو تم عمل Revoke له؛ ضع التوكن الجديد في Worker Secret باسم `BOT_TOKEN`.
- `/health` يعرض `webhookUrlMatchesWorker=false`: أعد تسجيل Webhook على رابط `/telegram/webhook` الخاص بهذا الـWorker مع نفس `WEBHOOK_SECRET`.

رسالة `/start` تُعالج دون الاعتماد على D1، حتى يمكن اختبار التوكن والمالك واستلام لوحة التحكم عند تعطل قاعدة البيانات. باقي عمليات البوت تحتاج D1 سليمًا.
